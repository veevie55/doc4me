# คัดลอกวัตถุผ่าน system clipboard ข้ามไฟล์และข้ามโปรแกรม · 2026-11-19

ขอบเขตตามคำสั่งผู้ใช้: คัดลอก/ตัด/วาง กล่องข้อความ รูปภาพ วัตถุ รูปร่าง ไอคอน ตาราง แผนภูมิ แบบจำลองสามมิติ SmartArt สมการ สัญลักษณ์พิเศษ และอักษรศิลป์ (WordArt) ในไฟล์เดียวกัน ข้ามไฟล์ และข้ามโปรแกรมผ่าน system clipboard

## ปัญหาที่พบก่อนแก้

1. **วัตถุไปไม่ถึงโปรแกรมอื่นหรือ Doc4Me หน้าต่างอื่น** clipboard ของ egui มีแค่ข้อความ Copy จึงส่งเฉพาะข้อความ วัตถุทุกชนิดหายเมื่อวางที่อื่น (rich clipboard เดิมอยู่ใน process เดียว)
2. **Copy วัตถุอย่างเดียวไม่อัปเดต system clipboard** ข้อความของวัตถุว่าง จึงไม่เรียก `copy_text` ข้อความหรือรูปเก่าจากโปรแกรมอื่นยังค้าง แล้ว Ctrl+V วางของเก่านั้นแทนวัตถุที่เพิ่งคัดลอก
3. **Cut จาก ribbon และเมนูคลิกขวาไม่เขียน system clipboard เลย** (มีแค่ Ctrl+X ที่เขียน) วางในโปรแกรมอื่นจึงได้ของเก่า
4. **Select All แล้ว Copy ในเอกสารที่ขึ้นต้นด้วยตาราง ได้แค่ย่อหน้า** `copy_blocks` เมื่อปลายสองข้างอยู่คนละ container (ในตารางกับนอกตาราง) แตกตารางเป็นย่อหน้า โครงสร้างตารางหายแม้วางในไฟล์เดียวกัน
5. **วาง HTML/RTF จากโปรแกรมอื่นได้แค่ข้อความธรรมดา** Paste ธรรมดาไม่อ่าน HTML/RTF ของ clipboard (มีเฉพาะ Paste Special เมื่อผู้เรียกส่งมาเอง)

## สิ่งที่แก้

- `crates/engine/src/clip_transfer.rs` (ใหม่): ทุก Copy/Cut สร้างรูปแบบกลาง
  - **HTML** รูปเป็น `data:` URI; วัตถุที่ HTML อธิบายไม่ได้ (รูปร่าง กล่องข้อความ WordArt กลุ่ม แผนภูมิ SmartArt สมการ) วาดเป็นรูปด้วย renderer ของเราเอง ขนาดเท่าวัตถุ alt เป็นข้อความ/รูปแบบเชิงเส้นของสมการ (สูงสุด 64 วัตถุต่อการคัดลอก ด้านละไม่เกิน 3,000 pt)
  - **สำเนา lossless** เป็นไฟล์ DOCX ฝังใน comment `<!--Doc4MeClipboard v1 id=… blocks=… docx=…-->` ของ HTML โปรแกรมอื่นไม่สนใจ comment นี้ Doc4Me หน้าต่าง/process อื่นอ่านกลับได้ครบ แก้ไขได้ (แผนภูมิ SmartArt กล่องข้อความ OLE สไตล์ ลำดับเลข เชิงอรรถ)
  - **RTF** (`\pngblip`) สำหรับ Windows และ **PNG** เมื่อคัดลอกวัตถุเดียว (รูปใช้ไบต์ PNG เดิม) พร้อม bitmap 24 บิต (`bmp_from_png`) สำหรับโปรแกรมที่อ่านแค่ bitmap
  - **ข้อความล้วน**
- `crates/ui-egui/src/system_clipboard.rs` (ใหม่) และ `WordApp::run`: Copy/Cut จากทุกทาง (คีย์ ribbon เมนูคลิกขวา ค้นหาคำสั่ง) ส่งให้ system clipboard จุดเดียว ไม่มีบริการ (เว็บ) ใช้ข้อความผ่าน egui ตามเดิม แม้ข้อความว่างก็เขียนทับของเก่า; Paste/Paste Special อ่าน HTML และ RTF ส่งให้ engine ถ้า HTML มีสำเนา Doc4Me จะมาก่อนรูปภาพบน clipboard (รูปนั้นมีไว้ให้โปรแกรมอื่น)
- `apps/doc4me/src/system_clipboard.rs` (ใหม่): Windows เขียนทุกรูปแบบในครั้งเดียวผ่าน `clipboard-win` (HTML Format, Rich Text Format, PNG, bitmap, ข้อความ CRLF) อ่าน HTML/RTF กลับโดยตรวจขนาดก่อนอ่าน; macOS/Linux/BSD ใช้ `arboard` เขียน HTML พร้อมข้อความ และอ่าน HTML กลับ (เก็บ connection เดียวตลอดอายุแอป เพื่อให้ X11 ยังให้บริการ clipboard)
- `edit.paste` รับ `html`/`rtf`: ลำดับคือ สำเนา Doc4Me (token ตรงกับของเรา = ใช้สำเนาในหน่วยความจำ; ไม่ตรง = สำเนาจากหน้าต่างอื่น ใช้ค่า "วางระหว่างเอกสาร") > ข้อความของเราเอง > HTML ของโปรแกรมอื่น > RTF (RTF มาก่อนเมื่อ HTML อ้างรูปเป็นไฟล์ local) > ข้อความ; โหมด Keep Text Only ใช้ข้อความของ clipboard
- `crates/doc/src/edit.rs` `copy_across_tables`: ช่วงเลือกที่ข้าม container เก็บตารางเป็นตาราง ตัดเป็นแถวเต็มจากแถวของปลายช่วง (แบบ Word) การรวมเซลล์แนวตั้งที่ต่อจากแถวที่ไม่ได้คัดลอกเริ่มใหม่ในแถวแรก

## ความปลอดภัย

ข้อมูล clipboard มาจากโปรแกรมอื่น ถือว่าไม่น่าเชื่อถือ: HTML ไม่เกิน 96 MB, payload DOCX ไม่เกิน 48 MB (ตรวจก่อน decode), header ต้องเป็น `v1` และ `blocks` เป็นตัวเลขที่ parse ได้, อ่านผ่าน DOCX reader ที่มีเพดานเดิม แล้ว `normalize_runs` และตรวจว่าจำนวนวัตถุตรงกับอักขระวัตถุทุกย่อหน้า (รวมกล่องข้อความ) ถ้าเสียจะไม่ใช้และวาง HTML/ข้อความแทน; การนำเข้าทรัพยากรผ่าน `clipboard::adopt` เดิม (รูปรวมไม่เกิน 128 MiB, ไม่เขียนทับชื่อซ้ำ) Windows ตรวจ `GetClipboardData` size ก่อนอ่าน ไม่มี panic path ใหม่

## หลักฐาน

- เทสต์ engine ใหม่ 10 รายการใน `crates/engine/src/tests_clip_transfer.rs`: วัตถุ 10 ชนิด (รูป รูปร่าง กล่องข้อความไทย WordArt ไทย ไอคอน 3D model แผนภูมิ SmartArt สมการ ตาราง) ไปถึงหน้าต่างอื่นเป็นชนิดเดิมพร้อมไบต์รูป; ข้อความตัวหนา + กล่องข้อความไทย; โปรแกรมอื่นได้รูปของรูปร่างใน HTML/RTF และสัญลักษณ์พิเศษเป็น Unicode; วัตถุเดียวได้ PNG และ BMP header ถูกต้อง; สำเนาของเราเองใช้สำเนาในหน่วยความจำ; HTML/RTF จากโปรแกรมอื่นวางพร้อมตัวหนา ตาราง รูป; Paste Special; payload เสีย 7 แบบไม่ panic และ fallback; สำเนาที่จบด้วยตารางไม่มีย่อหน้าเกิน; Select All ที่ขึ้นต้นด้วยตาราง
- เทสต์ UI ใหม่ 2 รายการใน `crates/ui-egui/src/system_clipboard.rs`: รูปร่างคัดลอกจากหน้าต่างหนึ่งวางอีกหน้าต่างเป็นรูปร่าง ไม่ใช่รูปที่อยู่ข้างกัน; ในหน้าต่างเดียวกัน; Cut เขียน clipboard; Copy โดยไม่ได้เลือกไม่เขียน; HTML จากโปรแกรมอื่นวางเป็นตัวหนา; clipboard ล้มเหลวยังคัดลอกได้
- โค้ด Windows (`clipboard-win`) ตรวจ `cargo check` และ `cargo clippy -D warnings` บน target `x86_64-pc-windows-gnu` ด้วย crate จำลองที่ใช้ฟังก์ชันเดียวกัน; CI Windows หลัง push เป็นตัวยืนยันสุดท้าย

## ข้อจำกัดที่ทราบ

- macOS/Linux/BSD: `arboard` เขียนได้ครั้งละชุดเดียว (HTML + ข้อความ) จึงไม่มี PNG/RTF แยก โปรแกรมที่รับเฉพาะรูป (เช่นโปรแกรมวาดภาพ) วางวัตถุไม่ได้ ส่วนโปรแกรมที่รับ HTML (LibreOffice, เบราว์เซอร์, อีเมล) ได้รูปผ่าน `data:` URI
- โปรแกรมอื่นได้รูปของรูปร่าง/แผนภูมิ/SmartArt/สมการ ไม่ใช่วัตถุที่แก้ไขได้ (Word เองก็ทำเช่นนี้กับโปรแกรมที่ไม่รู้จักรูปแบบของมัน); การวางกลับเข้า Word เป็นวัตถุ Office ที่แก้ไขได้ต้องใช้รูปแบบ OLE ของ Office ซึ่งไม่อยู่ในขอบเขต
- ไม่อ่านไฟล์ local ที่ HTML ของ clipboard อ้างถึง (`file:///…`); เมื่อ HTML อ้างรูปแบบนั้น (เช่น HTML ของ Word) และมี RTF ด้วย จะวาง RTF ก่อนเพราะ RTF ฝังรูปไว้ (PNG/JPEG); ถ้าไม่มี RTF รูปนั้นจะหาย
- เว็บ (WASM) ยังส่งเฉพาะข้อความ เพราะ clipboard API ของเบราว์เซอร์เป็นแบบ async
- ยังไม่ได้ทดสอบด้วยมือบน Windows/macOS จริงกับ Word/LibreOffice ในรอบนี้ (เครื่องนี้เป็น Linux container ไม่มี display)
